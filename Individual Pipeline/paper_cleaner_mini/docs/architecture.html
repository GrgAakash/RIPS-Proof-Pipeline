RIPS Proof Pipeline / component architecture

One theorem. One bounded packet.

Paper Cleaner Mini builds the context for one source-backed target. It follows whole-paper preparation; it does not replace it.

Component README Execution order Role boundaries Solver handoff

Proof-informed preparation. Mini's authoring roles can read the source proof. The solver receives a checked, restricted packet, not that full source. Leakage checks are safeguards, not a guarantee that all indirect hints are absent.

Execution order

The arXiv wrapper, run.py, prepares the source, runs Mini, then audits the packages. The later solver integration is a separate entry point.

  1. Prepare the whole paperPaper Cleaner Steps 1–5 download and index the source and select target IDs. Mini requires verified statement and paired-proof provenance.
  2. Freeze the target; draft the contextCode creates or validates target.tex and target.json. The author drafts Sections 0–5; code supplies the exact target as Section 6.
  3. Check, then repair within budgetDeterministic checks and the checker assess the draft. If issues remain, the repair role revises the editable body and both checks run again. The default budget is two repair rounds.
  4. Ship or excludeA package ships only when the checker passes and deterministic checks are clear. Failures are recorded in excluded.json. This decision is about packet readiness, not proof correctness.
  5. Audit independentlyaudit.py reviews packages and exclusions. The integrated gate checks the selected package's verdicts and current hashes before export.

Source: stage2.py, package_validation.py, and audit_gate.py.

Models propose; code controls the boundary

Author

Selects notation, assumptions, definitions, and permitted results from the source to build Sections 0–5.

Checker

Challenges sufficiency, self-containment, and leakage. Its passing verdict cannot override a deterministic failure.

Repair

Responds to concrete findings within the repair budget. It has no authority to change the frozen target.

The separate auditor reviews the finished artifacts. Model identities are configurable; separate roles do not necessarily mean different underlying models.

From packet to solver

python -m solver run-cleaner-solver begins from a prepared paper. It runs Mini and its audit, source-checks external Section 3 grants when present, then exports a solver bundle before starting S0–S6. Missing, stale, or failed setup evidence blocks that handoff.

ArtifactPurpose
target.mdThe frozen theorem statement.
skeleton.mdSections 0–5: the solver's permitted context.
allowed_support.mdThe explicit premise boundary.
setup_manifest.jsonInput condition, hashes, and setup evidence.
private/Gold proof and full source only when the private Final Checker is enabled; not part of S0–S6 input.

A hand-authored run-open-problem packet bypasses these preparation gates. See the bridge implementation and the input contract.

Inspect before spending

From Individual Pipeline/paper_cleaner_mini/, with the documented dependencies installed:

python run.py --arxiv 2604.04891 --print-plan

This prints subprocess commands without downloading the paper or calling a model. Live runs may send large amounts of paper text to the configured provider. Caching may reduce repeat calls, but is not a promise of a free rerun.
